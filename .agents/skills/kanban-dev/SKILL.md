# Kanban Dev

## 读取项目知识

本技能位于仓库的 `.agents/skills/kanban-dev/`；下列链接相对本文件解析。以包含 `kanban_code_structure.md` 和 `kanban/` 的仓库根目录为工作基准。

1. 读取根目录 `AGENTS.md` 和 [领域文档规则](../../../docs/agents/domain.md)，按规则读取已有术语表及相关 ADR。
2. 读取 [kanban_code_structure.md](../../../kanban_code_structure.md)，建立对模块职责、数据模型、IPC、业务调用链及验收边界的理解。直接使用仓库原文，不在技能内维护副本。
3. 根据需求定位并核对相关源码与现有测试。结构文档是导航，当前代码是实现事实；发现差异时在方案中标明。
4. 涉及需求或规格的 GitHub Issue 操作前读取 [issue-tracker.md](../../../docs/agents/issue-tracker.md)；分类时读取 [triage-labels.md](../../../docs/agents/triage-labels.md)。用户提供 Issue 时读取正文、标签和评论；按用户授权操作 tracker，不因调用技能就自动发布方案。

## 先研究方案

用户调用技能并说明需求时，默认进入研究阶段：只读检查代码、文档和已有证据，在对话中形成可评审的实现方案。此阶段不修改产品代码、配置或测试，不提前实现原型，也不把拟议行为写成结构文档中的已实现事实。

方案说明：

- 需求理解、范围和需要澄清的关键问题。
- 当前行为及相关文件、函数或调用链证据。
- 推荐实现方式、受影响模块，以及适用的数据、IPC、迁移或生命周期变化。
- 验收方式、风险及尚未验证的假设；区分静态分析、模拟测试与真实桌面/Herdr 验收。

方案结束时明确说明：依据本技能“先研究方案”的约定，当前等待用户确认后开发。普通需求描述、提问或继续讨论不视为开发许可。

## 获准后实施

用户明确说“可以开发”“开始实现”“按这个方案做”或作出等价授权后，实施已确认范围。沿用当前会话中仍有效的授权，不重复要求确认；新增未获授权的需求仍先研究。

实施前检查工作区现有改动，保留用户工作。按已确认方案完成代码和相应验证；具体检查以当前项目脚本和受影响模块为准。记录实际验证结果及未覆盖项，不把模拟 IPC 或前端构建通过当成真实桌面与 Herdr 验收通过。

## 开发完成时自动同步文档

每次通过本技能完成开发后，在最终交付前自动更新仓库原始 [kanban_code_structure.md](../../../kanban_code_structure.md)，无需用户另行提醒或批准。

- 依据最终代码增量修改相关章节：目录与职责、数据模型、IPC、调用链、边界或验证说明；删除本次改动导致的过时描述，保留其他仍有效内容和已有未提交编辑。
- 更新文档日期；只写已实现事实，将未完成事项和验证限制明确标出。
- 若改动不影响现有结构描述，仍在相关章节简要记录本次行为变化或修正及实际验证结论，避免无意义重写全文。
- 纯研究、方案讨论或开发中断时，不把计划更新为完成状态；若已产生部分代码改动，只记录实际落地部分并标明未完成。

完成条件：已确认范围的实现与适当验证结束，结构文档与最终代码一致。最终回复概述实现结果、验证情况和文档更新位置；存在阻碍时如实说明未完成项。
