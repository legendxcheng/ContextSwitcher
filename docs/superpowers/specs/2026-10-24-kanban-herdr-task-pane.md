# Kanban 三列紧凑布局、任务独立 pane 与右侧交互终端

日期：2026-10-24。状态：主流程已实现，验收结果与未覆盖项见[验收记录](../../verification/2026-10-24-kanban-herdr.md)。本文件保留经确认的需求边界。

跟踪 Issue：[GitHub #4](https://github.com/legendxcheng/ContextSwitcher/issues/4)。

## Problem Statement

用户在 Kanban 中管理开发任务，但目前需要离开看板，到 Herdr 中寻找对应 Agent 的界面。三列看板占满内容区，没有持续查看、操作当前任务终端的位置。

当前派发允许多张卡片选择同一个 Agent pane；卡片只记录最近一次派发的展示字符串。因此，即使增加点击切换，也可能让多个任务显示同一个终端，无法可靠区分任务上下文。

本规格中的 Project 指 Kanban 项目，Task 指 Kanban 任务卡片；它们不等同于 Python 主应用中的 ContextSwitcher Task。pane 是 Herdr 终端位置，Agent 是其中运行的编码助手。

## Solution

将三列等宽收窄，在右侧增加约一个调整前卡片宽度的、可拖动分隔线调整宽度的 Herdr 交互终端。用户点击【开发中】卡片，立即看到选中状态及对应任务标题，随后连接该任务独占的 pane，持续显示其界面，并允许输入、粘贴和回复确认。

每个正常进入【开发中】的任务必须持有经过验证、持久化的独立 pane 绑定。点击或切换只改变查看连接，不重复派发提示词、不重新启动 Agent，也不终止其他任务。

沿用当前“选择已有 Agent 并确认派发”的流程，仅允许选择未被其他任务占用的目标。没有可用目标时提供明确提示，用户在 Herdr 中准备独立 Agent 后刷新选择；本次不增加自动安装、登录或启动任意 Agent 的配置系统。

## User Stories

1. As a 看板用户, I want 三列等宽收窄, so that 右侧可以持续显示当前任务的终端。
2. As a 看板用户, I want 右侧初始宽度约为调整前一张卡片的宽度, so that 看板与终端能够同时使用。
3. As a 看板用户, I want 拖动分隔线调整终端宽度, so that 我可以阅读较长输出或完整的确认界面。
4. As a 小窗口用户, I want 看板可以单独横向滚动, so that 三列不会被无限压窄或遮住右侧终端。
5. As a 看板用户, I want 点击开发中的卡片后立即看到高亮与右侧任务标题变化, so that 我能确认当前选择。
6. As a 看板用户, I want 右侧显示选中任务所绑定 pane 的实时界面, so that 我无需手动寻找对应 Agent。
7. As a 看板用户, I want 在右侧终端输入、粘贴和回复 Agent 的确认问题, so that 我能在同一个窗口继续开发。
8. As a 看板用户, I want 终端输入时不触发看板快捷键, so that 我的输入不会被截走。
9. As a 看板用户, I want 每个开发中任务使用独立 pane, so that 切换卡片不会混淆正在执行的任务。
10. As a 派发用户, I want 已被其他任务占用的 Agent 显示为不可选并说明原因, so that 我能正确选择独立执行位置。
11. As a 派发用户, I want 后端也拒绝重复绑定, so that 并发操作或旧页面不能破坏独占规则。
12. As a 派发用户, I want 取消或明确失败时保留原任务状态, so that 卡片不会提前进入开发中。
13. As a 派发用户, I want 没有可用 Agent 时知道如何准备目标并刷新, so that 我可以继续完成派发。
14. As a 派发用户, I want 对同一任务再次派发时复用其有效绑定, so that 我可以延续当前上下文。
15. As a 看板用户, I want 连续快速切换任务时最终只显示最后一次选择, so that 慢响应不会覆盖新任务的界面。
16. As a 看板用户, I want 切换项目时清除旧项目的终端连接和选择, so that 我不会向错误项目输入。
17. As a 看板用户, I want 关闭看板或切换任务仅断开查看连接, so that Herdr 中的工作继续运行。
18. As a 看板用户, I want 重启看板后保留任务与 pane 的绑定, so that 我不必重新派发来恢复查看。
19. As a 看板用户, I want pane 消失、Agent 退出或 Herdr 断开时看到明确状态和恢复入口, so that 我不会把旧画面误认为仍然连接。
20. As a 看板用户, I want 一个任务连接失败不阻塞其他任务, so that 我仍能使用看板并切换到正常目标。
21. As a 旧版本用户, I want 原有任务、提示词和派发记录保留, so that 升级不会丢失工作内容。
22. As a 旧版本用户, I want 共享、缺失或失效的旧绑定显示修复提示, so that 我能为各任务明确选择独立 pane。
23. As a 旧版本用户, I want 修复绑定本身不自动发送旧提示词, so that 恢复连接不会重复执行任务。
24. As a 看板用户, I want 标记完成或删除卡片不会自动杀死 Herdr 中的进程, so that 看板整理不会破坏终端中的工作。
25. As a 验收人员, I want 在真实 Windows Tauri 与 Herdr 环境验证输入、切换、重连及独占绑定, so that 浏览器模拟不会被当成完整交付。

## Implementation Decisions

### 界面与交互

- 修改看板布局、任务选择、派发选择器；新增右侧终端面板。项目列表、编辑提示词和拖放流程保留。
- 宽窗口中左侧三列等宽且比原布局窄；右侧初始宽度以同一窗口尺寸下调整前卡片宽度为参考。默认 1280×800 目标约 280–320 CSS px，实施时根据实际边距校准；不是要求三个收窄后的列与终端四等分。
- 三列建议最小宽度 200 CSS px，终端最小宽度 280 CSS px；分隔线受可用区域约束。在 900×600 最小窗口下允许三列区域内部横向滚动，终端保持可见，页面不产生遮挡控件的整体横向溢出。终端可扩宽以操作交互式 CLI。
- 无选中任务时显示“选择一个开发中的任务查看终端”。点击未开发或完成卡片不自动连接终端，现有操作入口继续有效。
- 卡片主体可通过点击和键盘选择。编辑、再派发、完成、删除按钮以及拖拽结束不应意外触发卡片选择。
- 选中状态和任务标题在本地交互后立即更新；连接过程明确显示加载状态。“立即”不意味着保证跨进程连接零延迟，也不设置尚未测量的毫秒承诺。
- 旧终端在切换期间立即停止接收输入，旧画面清除或明确标为不可交互。每次选择产生连接代次，迟到的响应、输出与错误不能更新新代次。
- 项目切换、选中任务被删除或离开开发中时断开当前查看连接并清除选择。重复选择同一张已连接卡片不建立重复连接。
- 焦点进入终端后，普通字符、终端快捷键、粘贴与确认操作送给终端；看板快捷键排除终端、表单和可编辑区域。
- 自有界面文案使用稳定的本地化键及中文回退，遵守仓库本地化 ADR；React 侧采用等价资源访问边界，不依赖导入 Python 函数，也不扩大为全站文案重构。

### 独占绑定与派发

- 增加结构化任务绑定，至少记录 Task ID、Herdr session 身份、workspace ID、pane ID、校验状态。显示名称与历史派发字符串不能作为唯一身份来源。
- 第一版限定本机默认 Herdr session；身份键仍包含 session，避免后续扩展时误把不同 session 的同名 pane 视为同一目标。
- 有效绑定在同一 session 内跨所有 Kanban Project 唯一，不能只检查当前列或当前项目。任务最多有一个当前绑定；pane 最多归属一个任务。
- 绑定使用后端事务和数据库唯一约束保障，不能仅依赖前端过滤。外部 Herdr 调用不能长时间持有全局数据库锁。
- 派发前验证目标仍存在、属于项目解析得到的 workspace、包含可派发的 Agent，且未被另一任务绑定。workspace 名称歧义或目标身份变化时要求修复，不选择第一个匹配项。
- 现有 Agent 选择器显示占用情况；拖向 Agent、派发按钮、拖入开发中及后端命令都遵守同一规则。取消派发不能预占目标。
- 确认后先持久化本次派发的身份与目标预占，再执行发送；收到明确成功后提交快照和开发中状态。直接更新状态的入口不能绕过“成功派发及有效独占绑定”的前置条件。
- 对同一任务的有效绑定再次派发复用原 pane；普通再派发不允许静默更换目标。目标失效时先完成明确的绑定修复，再由用户决定是否发送提示词。
- 明确未发送的失败释放本次临时预占并保留原状态。超时、进程中断或发送成功但数据库提交失败属于结果待核实：保留操作身份、目标及必要恢复证据，不自动重发、不伪装成功；提供核实后恢复入口，并允许其他任务使用其他 pane。
- 同一任务重复提交或两个任务同时抢占同一 pane 时，不允许重复发送或双重占用。恢复中的同一目标可以被暂时隔离，不能阻塞全局派发。
- 标记完成或移回未开发不自动关闭 Agent，也不自动把仍存在的绑定交给其他任务。保留该任务绑定以支持重新进入开发中继续上下文；第一版不做已完成任务的自动 pane 池复用。
- 删除任务解除绑定，断开查看连接但不关闭 pane、Agent 或 Herdr server。未来再次手动选择该 pane 属于用户的明确选择，不承诺删除后仍保留卡片上下文隔离。

### 终端接入与生命周期

- 目标是嵌入任务 Agent 的可交互终端界面，不是把外部 Windows Terminal 顶层窗口搬进 WebView，也不以只读日志查看器作为最终交付。
- 初始技术首选为终端模拟组件、Rust 管理的 Windows 伪终端连接及 `agent attach`。实施实测该 Windows 版本不支持直接 attach，因此采用同版本可用的 `terminal session control` JSONL 可写控制流；已验证输入、尺寸变化和安全释放。组件/库选择不作为业务契约。
- 用一个终端会话服务管理连接、输入、尺寸变化和断开；通过现有 Tauri IPC 作为应用边界，输出使用带连接身份的事件或通道。前端按 Task ID 请求，后端解析并再次验证绑定，不能信任任意前端 pane 参数。
- 输入必须同时验证当前连接身份、任务绑定和连接状态；切换、断线、身份不确定时禁用输入。pane ID 被重用或 Agent 身份无法确认时，不静默向新的占用者发送内容。
- 断开仅释放本应用持有的 attachment、伪终端及监听器；不能对底层 pane 发送退出、关闭或终止命令。应用异常退出后底层 Herdr 工作应继续。
- 不默认使用强制接管选项；目标存在其他交互连接时说明情况，不静默抢占。若当前 Herdr 版本无法满足交互连接或安全断开，需要记录具体能力缺口，再决定版本兼容方案；不能自行降级为只读并宣布完成。
- 连接建立失败有有限超时和明确重试入口；只重连查看连接，不自动重发任务。切换任务后旧重试必须停止。输出队列、滚动缓存及连接数量有界，不能因长输出耗尽内存。

### 旧数据兼容与修复

- 增加可重复执行的版本化数据库迁移；保留现有 Task、提示词、派发时间、目标文本与快照，不用旧字符串替代新绑定实体。
- 旧派发记录只作为候选目标线索；必须结合当前 session、workspace、pane 与占用情况核实后才能成为有效绑定。
- 多个旧任务指向同一 pane 时全部标为待修复，不自动选定所有者，不复制历史对话，不重新发送历史提示词。用户为任务逐个确认独立目标，修复操作也受后端唯一约束保护。
- 旧开发中任务允许暂时处于“待修复”状态，保留原列和内容，但不能连接或输入到未经核实的目标。它们是迁移兼容状态，不代表满足独占规则；所有新派发必须满足规则。
- Herdr 重启或恢复后重新验证绑定，不仅比较显示名称；目标无法可靠识别时提供修复入口。

## Testing Decisions

用户已确认：以“用户操作看板 → Tauri 命令 → 任务与 pane 绑定”为主测试入口，并使用真实 Windows Herdr 验收终端输入、切换和重连；浏览器模拟测试只验证界面。

- 好测试观察可见状态、实际持久化结果、目标身份、发送次数及底层进程是否继续；不绑定组件私有状态、CSS 类名或内部辅助函数的实现细节。
- 优先扩展现有 Vitest 与 Testing Library 看板交互测试，沿用模拟 Tauri invoke 的入口，验证选择、派发确认、取消、失败、占用提示、快速切换、旧响应隔离、项目切换、控件事件传播及快捷键隔离。模拟终端事件只证明前端隔离行为。
- 后端在 Tauri 命令所调用的应用服务入口验证真实临时 SQLite 与独占规则；外部 Herdr/attachment 使用一个可替换的集成边界模拟错误和迟到响应。避免为每个组件或 CLI 子命令创建独立测试框架。
- 后端必要场景：跨项目重复绑定、并发抢占、同一任务重复提交、直接改为开发中的绕过尝试、发送失败、结果未知、成功后落库失败、恢复不重发、绑定修复冲突、重复迁移、旧共享绑定与失效身份。
- 现有 Python Herdr workspace、terminal 与 integration 测试可参考其外部系统边界和故障场景；它们不能替代独立 Tauri 应用的新功能验证。
- 布局使用 1280×800、900×600 及至少一个更宽桌面尺寸检查：右侧初始宽度、三列收窄、分隔线边界、内部滚动、按钮可访问性、长标题与长输出。实际 Windows 下补查不同缩放比例和终端 resize。
- 真实桌面验收必须使用隔离的测试 Project、SQLite 数据和 Herdr pane，不向用户正在工作的 Agent 发送测试文本。

真实 Windows / Tauri / Herdr 的必验场景：

1. 为任务 A、B 分别准备独立 Agent pane 并派发，绑定经重启看板仍可恢复。
2. 点击 A/B 时标题立即变化，最终只显示各自 pane；快速 A→B→A 和快速切项目没有旧输出混入或错误输入。
3. 在 A 输入测试内容，只有 A 收到；在 B 回复交互确认，只有 B 收到；普通字符、粘贴和终端控制键不触发看板快捷键。
4. 调整分隔线及窗口尺寸，终端列行同步更新，内容和交互控件仍可使用。
5. 两个任务尝试绑定同一 pane，包括不同 Project 和并发命令，只有合法占用者成功，另一任务不发送提示词。
6. 切换任务、关闭看板、终止本应用 attachment 后，A/B 的底层工作继续；不存在连接监听器无限增加。
7. 关闭目标 pane、断开 Herdr 或制造连接超时，界面说明失败，其他任务仍可使用；恢复查看不重发提示词。
8. 旧共享绑定显示待修复；修复为独立目标后正常查看，旧提示词不自动执行。
9. 标记完成、移回未开发与删除时，选择和查看连接按规则清理，底层 Agent 不被终止。

实施完成时记录前端测试与构建、Rust 测试与检查、真实桌面验收的各自结果。未完成真实 Herdr 验收时必须明确标为未验收，不能用浏览器预览代替。

## Out of Scope

- 重写 Python/PySide6 主程序、自动切换 ContextSwitcher 窗口或同步两套任务状态。
- 自动安装 Agent、登录账号、推断任意 Agent 启动命令或自动为所有任务创建工作区。
- 多机器、远程 SSH、多 Herdr session 的用户选择与管理界面。
- 自动完成任务、按 Agent 状态自动移动卡片、后台任务调度及 Agent 会话历史管理。
- 把旧共享 pane 的历史对话拆分成多个独立任务会话。
- 自动关闭已完成任务的 pane、自动清理 Agent、跨任务复用已完成任务的绑定池。
- 保证每个任务使用独立代码目录或 Git worktree。独立 pane 隔离终端上下文，不等于隔离文件修改。
- 重新设计提示词编辑器、引用系统、项目管理或整个应用的多语言基础设施。

## Further Notes

- 已确认的产品范围：三列收窄；右侧可交互终端；点击开发中卡片切换；每个开发中任务独占 pane；用户已确认上述测试边界。
- 独立 pane 的第一版分配策略为“选择未被占用的已有 Agent”；这是沿用现有流程的实施决策。没有可用目标时明确提示准备目标，不静默选择已占用 pane。
- 本机已检查到 Herdr 提供 agent attach、agent read 与 agent focus 命令；这仅证明接口存在，不构成内嵌终端、性能或生命周期已验收的证据。
- 规格建立时只保存最近派发文本目标；实施后增加结构化绑定、持久化派发操作及可写终端控制流。完成程度以验收记录为准。
- 项目未提供现成 GLOSSARY。若后续执行 domain-modeling，建议补录 Kanban Task、ContextSwitcher Task、Project、workspace、pane、Agent、任务绑定与查看连接的区别。
- 已按仓库的 issue tracker 配置发布到 GitHub Issue #4，标签为 ready-for-agent。后续需求变更同步维护 Issue 与本地规格。
