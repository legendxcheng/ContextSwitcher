# Kanban 首批重构：测试按场景组织与 Herdr 适配层职责拆分

## Problem Statement

Kanban 的生命周期、派发、看板组件回归和 Herdr CLI 适配逐步积累到少数长文件中。维护者查找某项规则或补充测试时，需要同时理解多个无关场景，测试替身和准备逻辑也容易互相影响，增加了修改和审查成本。

2026-10-24 再次核对当前工作区时，生命周期模块约 1429 行、派发模块约 1008 行、看板组件测试约 1111 行、Herdr 适配模块约 890 行；这些数字包含内嵌测试，且会随其他正在进行的工作变化。生命周期与派发模块的长度主要来自测试，不能据此认定其业务逻辑也需要拆散。

用户已选择此前建议的首批范围：整理生命周期与派发测试，按功能拆分看板组件测试，再拆分 Herdr 适配层内部职责。

## Solution

通过职责明确、可分批验证的内部重构，让维护者能直接找到相关规则和回归场景。生命周期和派发规则继续通过原有业务服务协调，测试移至按场景组织的独立模块；看板测试按用户行为分组；Herdr 对外适配入口继续稳定，内部集中封装进程执行、workspace 目录元数据及 Codex 会话适配。

用户可见行为以实施前当前工作区为基线，包括异步启动、任务独占 pane、同 workspace 共用 kanban Tab、会话隔离、未知结果核实、异常任务删除和终端查看连接。重构通过现有测试入口验证这些行为，并补充受影响真实链路的验收证据。

## User Stories

1. 作为维护者，我希望生命周期测试按启动、恢复、完成清理和异常取消组织，以便快速定位某项规则的回归。
2. 作为维护者，我希望派发测试按独占绑定、发送结果、人工核实和并发组织，以便评估一致性改动的影响。
3. 作为维护者，我希望业务实现阅读不被大段测试打断，以便理解完整的状态转换与事务顺序。
4. 作为维护者，我希望看板测试按用户场景组织，以便只阅读与本次需求相关的断言。
5. 作为维护者，我希望测试数据与 IPC 替身可以复用且每个用例独立重置，以便测试不依赖执行顺序。
6. 作为维护者，我希望已有测试在整理后继续由默认测试命令发现，以便不遗漏现有回归。
7. 作为维护者，我希望常规测试与需要真实 Herdr 的测试清楚区分，以便不会误向个人工作 pane 发送测试输入。
8. 作为维护者，我希望进程执行、超时和响应解析集中维护，以便不同 Herdr 操作遵守一致的错误语义。
9. 作为维护者，我希望 workspace 目录元数据解析独立封装，以便修改格式兼容规则时能准确定位影响。
10. 作为维护者，我希望 Codex 启动、恢复和会话身份读取集中组织，以便审查会话隔离规则。
11. 作为 Kanban 用户，我希望拖入开发中仍立即显示准备状态，以便后台准备期间继续处理其他任务。
12. 作为 Kanban 用户，我希望重复启动不会重复派发提示词，以便不会产生重复工作。
13. 作为 Kanban 用户，我希望同 workspace 中的任务继续共用 kanban Tab 并各自独占 pane，以便保持当前窗口组织和任务隔离。
14. 作为 Kanban 用户，我希望一个任务完成时只关闭其所属 pane，以便同 Tab 的其他任务继续运行。
15. 作为 Kanban 用户，我希望重新开发已保存会话的任务时恢复准确会话且不重发原提示词，以便保留上下文。
16. 作为 Kanban 用户，我希望目标进程身份变化时保留恢复提示，以便应用不会向错误会话输入或关闭错误 pane。
17. 作为 Kanban 用户，我希望启动、发送或关闭结果不确定时继续保留核实证据，以便安全确认结果且不自动重放。
18. 作为 Kanban 用户，我希望异常任务仍能通过现有删除入口移除，以便个别未决操作不妨碍后续工作。
19. 作为 Kanban 用户，我希望删除后的迟到结果不能恢复原任务或占用，以便已删除任务不会再次影响看板。
20. 作为 Kanban 用户，我希望切项目、选任务、编辑、归档和状态刷新保持现有行为，以便内部重构不改变操作习惯。
21. 作为 Kanban 用户，我希望切任务或关闭查看连接时只释放本应用的对应终端连接，以便其他任务和 Herdr 进程继续工作。
22. 作为审查者，我希望重构前后的测试场景有对应关系，以便确认文件移动没有悄悄减少覆盖。
23. 作为后续接手者，我希望代码结构说明反映最终模块职责与实际验证限制，以便能据此继续维护。

## Implementation Decisions

- 首批限定为四项：生命周期内嵌测试整理、派发内嵌测试整理、看板组件测试按功能拆分、Herdr 适配层职责拆分。按这个顺序分批实施、检查差异并验证。
- 生命周期与派发的生产业务逻辑继续由现有 Workflow 服务协调。提取测试不作为重写状态机、拆分事务或更换服务接口的理由。
- 生命周期测试按启动与恢复、完成与清理、删除与迟到结果、并发与未知结果等业务场景组织。派发测试按独占绑定、发送与恢复、归档删除互斥等场景组织，真实环境测试单独辨识。
- 看板测试按项目导航、任务表单与优先级、删除归档、实时 Agent 状态、任务选择与终端、自动启动与手动派发等用户行为组织。跨功能用例按其主要断言归属保留，不为凑文件长度拆散一个完整用例。
- 可提取范围明确的测试数据工厂和准备函数。每个用例单独重置可变数据、IPC 调用记录、订阅、定时器和终端替身；不依赖测试文件之间共享可变状态或执行顺序。测试工具层不复制完整业务状态机。
- Herdr 适配保留现有 Cli/Herdr 对外入口和调用方式；提取内部的 CLI 进程执行与响应处理、workspace 目录元数据、Codex 会话适配三个职责。具体内部文件布局由实现时的依赖关系决定，不为方便测试扩大公开 API。
- CLI 执行职责统一保留无 shell 参数传递、有界执行与输出读取、当前各命令响应规则，以及明确失败和不确定结果的区别。
- workspace 元数据职责继续保留 session 隔离、显式路径覆盖、格式版本与读取上限验证，以及目录缺失时现有降级语义。
- Codex 适配职责集中现有启动与精确恢复、会话 UUID 核验、Windows 进程证据和提交兼容。已有进程身份核验能力继续复用，避免出现第二套身份判断。
- 当前已提取的共享 Tab 拓扑和 pane 分配证据模块继续复用。自动分配的 workspace 级互斥范围、创建前快照、未知候选隔离、有效绑定兼容和创建结果核实行为属于本次行为保持基线。
- 所有会产生外部副作用的操作继续保留执行前后目标身份、任务存在性及操作有效性检查；数据库互斥锁不跨外部 Herdr 调用持有。未知结果不自动重发，不将准备状态视为就绪，不从历史或其他 pane 猜会话 ID。
- 现有 Tauri IPC 命令、参数、返回结构、错误键、SQLite 表结构、迁移语义和数据目录不因本次重构改变，不新增配置迁移。
- 600 行是维护审查信号。对本次目标按职责减少单文件负担，测试提取后若仍存在超过 600 行的文件，应说明其职责、未继续拆分的理由及是否需要后续处理；不删断言或压缩排版来满足行数。
- 实施前重新记录当前工作区和测试基线，保留其他未提交工作。当前工作区是行为基线，不能用较早提交覆盖其已落地功能；测试失败须区分基线问题与本次引入问题。
- 开发完成时同步原始代码结构文档：更新模块职责、测试组织、调用关系、日期及实际验收结论，并校正相关章节已过时的迁移版本说明。规格中的计划不提前写成已实现事实。

## Testing Decisions

- 优先沿用已有高层入口，不为每个新文件新建测试接口。主要自动化验收边界为真实 React 组件的用户操作与现有 Rust 业务服务入口；CLI 协议替身仅补充外部适配不能由业务替身证明的部分。
- 好的测试检查可观察结果：界面状态、选中任务、调用目标与副作用次数、SQLite 持久化结果、重启恢复和底层 pane 生命周期。不检查私有函数名、新文件路径、模块数量或纯内部调用顺序。
- 前端沿用 Testing Library 与现有 Tauri/xterm 替身，通过点击、拖放、表单和事件刷新验证行为，覆盖本次拆分前已有看板场景；执行现有前端测试入口和生产构建，构建包含 TypeScript 检查。
- Rust 沿用 Workflow 服务入口、真实 SQLite 内存库及文件重开、已有 FakeHerdr 和故障注入方式，验证独占绑定、重复操作不重发、发送成功后落库失败、启动与关闭未知、错误会话、任务删除后的迟到请求、并发分配及恢复隔离。
- 适配层沿用现有真实 Cli 配合 Herdr CLI 替身的验证方式，核对命令参数、目标身份、响应错误分类和可观察副作用。特别保留 Windows 粘贴后单次提交、会话不串 pane、创建结果丢失和删除后不继续操作的覆盖。
- workspace 元数据规则继续通过已有输入/输出场景验证，包含版本、目录缺失、session 隔离与读取失败；仅在提取改变依赖边界、现有覆盖不足时补充必要测试。
- 整理前后记录测试用例与默认 ignored 用例的对应关系、数量和执行结果，核对测试发现范围，避免通过跳过、删除或缩小断言使重构表面通过。真实环境测试仍须显式选择隔离 workspace。
- 执行现有 Rust 常规回归、锁文件约束下的编译检查及格式检查；不为重构引入依赖升级或修改锁文件。
- Herdr 适配拆分后，在独立测试数据目录和专用验收 workspace 中补充真实 Windows Tauri/WebView2、Herdr 与 Codex 核心链路：双任务启动及 pane 独占/共用 Tab、完成一项不影响另一项、保存后重新打开应用并精确恢复且不重发、终端选择与安全断开。不得操作用户现有工作 pane。
- 真实桌面验收、真实 Cli 配协议替身、浏览器模拟 IPC 和 Rust 业务替身是分别记录的证据。环境缺失或验收未执行时明确列为未覆盖，不沿用历史结果冒充本次通过。
- 完成标准为：四项范围均完成；既有场景仍被发现且通过，或基线失败有可复核证据；受影响新边界的必要覆盖通过；结构文档与最终代码一致；真实链路结果及任何未覆盖项明确列出。

## Out of Scope

- Python 主程序、任务管理器、Qt 主窗口、VS Code 辅助模块和演示脚本的重构。
- workspace 项目服务测试的进一步拆分，以及全局样式文件拆分。
- 更换前端状态管理、重写生命周期/派发状态机、重做终端协议、改变共享 Tab 分配策略或修改错误恢复规则。
- 新增用户功能、布局或交互调整、数据迁移、IPC 契约变更、依赖升级和性能目标变更。
- 将其他并行需求、已有缺陷修复或全仓库超过 600 行的文件自动纳入本批。
- 安装包分发、安装升级、发布上线或重启用户当前应用。
