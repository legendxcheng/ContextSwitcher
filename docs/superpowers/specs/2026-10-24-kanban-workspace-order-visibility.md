## Problem Statement

Kanban 项目顺序与 Herdr workspace 顺序不一致；在 Herdr 关闭的 workspace 仍占据看板侧栏。用户需要手动寻找对应项目，并容易进入已经失效的工作空间。

当前同步会保留 workspace 身份与任务，但项目查询按本地创建时间排序，消失的 workspace 只标记失联并继续显示。每次刷新又先展示本地缓存，因此只调整在线结果不能解决刷新与重启后的表现。

## Solution

Kanban 正常项目列表跟随 Herdr workspace 的顺序和存在状态。成功同步确认 workspace 已关闭后隐藏对应项目，保留其任务、提示词、绑定、会话和操作记录。同一 session 与 workspace ID 再次出现时恢复原项目；同名新 ID 不接管旧任务。

保存最近成功同步的顺序和可见状态，启动缓存与在线列表使用同一规则。Herdr 请求失败保留最近有效列表并显示同步错误。当前项目被隐藏后选择第一个可见项目；没有可见项目时显示空态，释放原终端查看连接。

## User Stories

1. 作为 Kanban 用户，我希望项目按 Herdr workspace 顺序排列，以便快速定位相同工作空间。
2. 作为 Kanban 用户，我希望 Herdr 调整顺序后下一次同步更新看板，以便两边顺序保持一致。
3. 作为 Kanban 用户，我希望新出现的 workspace 插入 Herdr 对应位置，以便不会总被追加到列表末尾。
4. 作为 Kanban 用户，我希望重启看板后缓存保留最近确认的顺序，以便等待连接时列表不跳回创建顺序。
5. 作为 Kanban 用户，我希望刷新期间保留已确认的列表，以便旧缓存不会造成闪烁或选中项跳动。
6. 作为 Kanban 用户，我希望 Herdr 中关闭的 workspace 在成功同步后从正常列表消失，以便列表只保留仍可用的已关联工作空间。
7. 作为 Kanban 用户，我希望关闭非当前 workspace 不改变我的选择，以便继续当前工作。
8. 作为 Kanban 用户，我希望当前 workspace 消失后自动选中第一个可见项目，以便继续处理其他工作。
9. 作为 Kanban 用户，我希望所有已关联 workspace 关闭且没有其他可见项目时显示空态，以便不继续展示旧看板。
10. 作为 Kanban 用户，我希望切离消失的 workspace 时释放原终端查看连接，以便不会把输入发往旧目标。
11. 作为 Kanban 用户，我希望单纯排序不重建当前看板和终端，以便正在查看的任务保持稳定。
12. 作为 Kanban 用户，我希望关闭 workspace 后任务、提示词、归档和会话记录仍被保存，以便外部关闭不会造成数据丢失。
13. 作为 Kanban 用户，我希望同一 workspace ID 恢复后重新显示原项目与任务，以便继续原有工作。
14. 作为 Kanban 用户，我希望同名但不同 ID 的 workspace 不继承旧任务，以便任务归属不会混淆。
15. 作为 Kanban 用户，我希望 Herdr 超时、断线或返回无效数据时保留最近有效列表，以便连接问题不会被误判为关闭全部 workspace。
16. 作为 Kanban 用户，我希望成功返回空列表与连接失败有不同结果，以便真实关闭能生效而故障不会清空界面。
17. 作为 Kanban 用户，我希望离线重启后已隐藏项目仍保持隐藏，以便关闭过的 workspace 不再冒出。
18. 作为旧数据用户，我希望未关联项目仍保留原有处理入口，以便旧数据不会被本次隐藏规则误伤。
19. 作为 Kanban 用户，我希望已明确本地移除的 workspace 仍遵守排除规则，以便同步不会擅自重新添加。
20. 作为 Kanban 用户，我希望未决创建、派发及生命周期记录保持原样，以便排序与隐藏不会伪造成功、重发提示词或破坏核实证据。

## Implementation Decisions

- Herdr 在线 workspace 列表为顺序和存在状态的权威来源。沿用现有 CLI 适配与稳定 session + workspace ID，不按名称、ID 字典序或本地创建时间猜顺序；本机列表顺序与返回的 number 一致。
- 在 Project 持久化中增加可空的 workspace 顺序字段，采用幂等增量迁移。旧记录首次成功同步前保留稳定回退顺序；未关联项目保留并放在已排序关联项目之后。
- 同步服务在一个短事务内更新顺序、存在状态与现有名称/目录信息；外部查询仍在数据库锁外。查询失败或事务失败不提交部分排序/隐藏结果。
- 区分内部完整项目查询与供正常导航使用的项目列表。完整记录仍可用于稳定身份匹配、显式关联、未决操作恢复及历史数据检查；导航列表隐藏已确认 missing 的关联项目。缓存列表 IPC 与同步快照遵循同一可见性及排序规则，避免仅前端过滤造成重启回退。
- 未决创建与本地排除继续遵守现有保护。在线存在且已经关联的项目不能仅因未决操作被跳过就误标消失；隐藏依据实际在线身份集合。
- 不删除本地 Project，不迁移或清空其任务与历史，不写入本地移除排除记录。同一身份重新出现恢复原 Project ID；同名不同身份按原有独立导入规则处理。
- 前端缓存用于初始化；已有有效界面后焦点/定时刷新保持当前列表直到收到新的成功同步结果。显式刷新或本地 CRUD 后可以重新读取持久化导航，使离线本地删除等操作仍能立即生效。保留在途请求合并与迟到结果隔离，在线失败更新同步错误及必要的未决操作视图。
- 当前选择依旧以 Project ID 保持。仅当其不在可见列表时选择首项或空值，复用已有看板卸载与终端连接释放流程；排序不触发切项目。只释放 Kanban 查看连接，不发送 Herdr close 或终止 Agent。
- 继续采用启动、窗口焦点、手动及前台每 15 秒刷新；不新增 Herdr 推送协议，不承诺关闭瞬间同步。
- 既有多 session 身份隔离、本地排除、目录回退、关联守卫和创建恢复语义保持；不新增 session 管理界面。
- 实施完成同步更新代码结构文档和实际验收记录，保留工作区已有无关修改。

## Testing Decisions

- 用户已确认测试边界：项目应用服务＋真实 SQLite 为主要业务测试入口，App 组件验证用户可见交互，另做隔离 Tauri/Herdr 验收。优先复用现有边界，不为 SQL 或 CLI 内部步骤逐一建立测试模型。
- 好的测试断言返回列表顺序、可见项目、稳定身份、任务与历史保留、当前选择和连接释放等可观察结果，不只断言字段或内部方法被调用。
- 服务测试复用已有 workspace 同步的 Herdr 替身、真实 SQLite 与关闭重开先例。覆盖初始排序、外部重排、新 workspace 插入、重复同步、关闭部分/全部、同 ID 恢复、同名新 ID、离线失败、成功空列表、旧库迁移、重启缓存、事务回滚、未关联项目与未决操作。
- App 测试复用现有模拟 Tauri IPC 与终端边界。验证重排保持选中项目与连接、隐藏非当前项目不抢选、隐藏当前项目切首项并释放连接、全部消失展示空态、慢刷新与失败保留界面、常规刷新不重放旧缓存而显式本地变更仍可刷新缓存，以及合并请求不接受过期快照。
- 执行前端测试、类型/生产构建与 Rust 相关测试及格式检查。已有无关失败单独说明，不能静默忽略或改写其他任务实现。
- 隔离桌面验收使用独立 SQLite 与明确本次创建的 Herdr 测试资源，验证真实 Tauri IPC 返回与侧栏、关闭后的同步、焦点刷新、重启缓存；只清理本次测试资源。真实 Herdr 如果没有可自动操作的重排入口，则实际顺序对比与替身重排分别记录，不改写 Herdr 会话文件模拟真实重排。
- 模拟 IPC 或 CLI 替身不算真实 Herdr 验收。真实桌面、Herdr、构建和自动化测试各自记录通过与未覆盖项。

## Out of Scope

- 自动删除项目数据、关闭用户 workspace、停止 Agent、自动发送提示词或改写任务业务状态。
- 新增隐藏项目管理/恢复页面、批量清理、跨 workspace 合并或同名任务迁移。
- Kanban 内拖拽排序、双向同步 workspace 顺序、Herdr 升级或修改其持久化文件。
- 新增多 session 管理、改变既有未关联项目修复流程、改变 Agent 归属与生命周期协议。
- 自动安装新版本或重启用户正在使用的 Kanban/Herdr。
