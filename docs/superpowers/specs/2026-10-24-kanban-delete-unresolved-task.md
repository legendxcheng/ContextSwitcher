# Kanban 异常任务可通过现有删除按钮删除

## Problem Statement

用户启动任务后遇到 Herdr `agent_not_found`。任务保存为启动结果未知，并保留终端占用。前端禁用删除按钮，后端也拒绝删除存在未决操作的任务。即使用户已关闭对应终端，卡片仍可能停留在异常状态，用户无法清除不再需要的任务。

用户最终明确要求：“其实只要删除按钮能生效就行。”删除不应以修复启动、核实派发结果或恢复 Herdr 连接为前提。

## Solution

使用卡片原有的删除按钮及确认框。用户确认后，可以删除包含未决启动、未决派发、失败或待清理状态的任务；无需先核实结果或关闭 Herdr 窗口。

删除成功后卡片从看板消失，任务占用和本应用的终端查看连接被释放。刷新、切换项目、重启应用，以及后台操作的迟到结果均不能使卡片恢复。删除失败时保留卡片并显示实际错误，用户可以重试。

不增加“放弃并删除”、强制删除模式或额外恢复流程。

## User Stories

1. As a 看板用户, I want 使用原有删除按钮删除异常任务, so that 我不需要寻找新的操作入口。
2. As a 看板用户, I want 启动结果未知时仍能删除任务, so that 启动报错不会永久锁住卡片。
3. As a 看板用户, I want 派发结果未知时仍能删除任务, so that 我无需先人工确认是否发送成功。
4. As a 看板用户, I want 启动或派发尚未结束时也能提交删除, so that 我可以停止管理不再需要的任务。
5. As a 看板用户, I want 删除失败或待清理的任务, so that 清理故障不会阻止我整理看板。
6. As a 看板用户, I want Herdr 不可用时仍能删除本地任务, so that 删除不依赖外部服务恢复。
7. As a 看板用户, I want 绑定窗口已关闭或 Agent 已不存在时仍能删除, so that 失效绑定不会阻塞操作。
8. As a 看板用户, I want 保留现有删除确认框并能取消, so that 误点不会直接删除任务。
9. As a 看板用户, I want 删除成功后卡片和计数及时更新, so that 我能确认操作已经完成。
10. As a 看板用户, I want 删除当前选中任务后释放查看连接并沿用现有选择回退, so that 其他任务仍能正常查看。
11. As a 看板用户, I want 刷新或重启后已删除任务不再出现, so that 删除是持久有效的。
12. As a 看板用户, I want 后台迟到结果不能恢复已删除任务或重新占用终端, so that 异常任务不会再次干扰工作。
13. As a 看板用户, I want 删除不触发重新启动或重复发送提示词, so that 删除不会额外执行任务。
14. As a 看板用户, I want 删除一张任务不影响其他任务和 Herdr 进程, so that 我能继续现有工作。
15. As a 看板用户, I want 删除遇到本地存储错误时得到明确提示并可重试, so that 界面不会把失败显示为成功。

## Implementation Decisions

- 调整卡片操作的禁用范围：未决状态、任务启动或派发中的通用忙碌状态不再禁用删除。删除自身执行中仍防止重复点击。编辑、拖动和派发的现有规则不因本规格改变。
- 沿用现有删除 IPC 的调用方式、任务 ID 和删除确认交互；必要的后端协调集中到删除应用服务，不要求前端先调用恢复接口。
- 后端不再把生命周期或派发未决状态当作拒绝删除的理由。任务删除、绑定释放及对未决操作的终止处理保持事务一致性；存储失败时不得只删掉部分状态。
- 删除必须让旧操作失去后续更新该任务、保存会话或绑定终端的权限。使用持久化终止标记或等价的任务存在性与操作有效性校验，不能仅修改前端按钮或绕过守卫。
- 保留历史派发是否成功、结果未知等事实，不把删除伪装成派发成功或确认未发送；终止管理与发送结果是不同事实。记录不得在重启时被重新当作可恢复任务。
- 删除提交后，后台工作在下一次副作用前检查任务及操作有效性，不继续启动后续步骤或自动重发。已交给 Herdr 的在途请求无法保证撤销；其迟到结果必须被隔离，不得恢复任务或占用。
- 删除不调用 Herdr 来判断是否允许删除，不等待 Agent 退出或远端清理成功。沿用本地删除语义，释放本应用的终端查看连接，不额外关闭 Herdr pane、终止 Agent 或撤销已发生的文件修改。
- 以唯一任务 ID 隔离删除及迟到回调；新建同名任务不继承已删除任务的操作。
- 成功后沿用现有任务列表刷新、计数和选择回退；失败保留卡片并恢复可重试入口。并发重复删除同一任务应得到一致的已删除结果，不触及其他任务。
- 不预设新表或新 IPC。若现有记录无法表达终止状态，只做实现上述契约所需的最小兼容迁移。新增应用文案遵循现有稳定翻译键规则。

## Testing Decisions

- 用户已确认验收边界：直接点击现有删除按钮，确认后异常卡片消失；Herdr 不可用或窗口已关闭也能删除；刷新、重启和后台迟到结果不能让卡片恢复。
- 主测试边界为用户删除行为：现有看板组件入口验证可点击、确认/取消、调用结果及选择回退；同一删除 IPC 背后的应用服务使用真实 SQLite 和可控 Herdr 替身验证持久化与并发。尽量复用这两个已有层级，不为内部辅助函数新增独立测试体系。
- 既有测试依据包括看板删除当前选中任务后的终端释放与选择回退测试，以及工作流中真实 SQLite、未知派发、重启恢复和迟到操作保护的测试设施。
- 覆盖正常任务、启动失败、启动 unknown、派发 unknown、pending 启动/派发、完成后待清理。各场景验证现有删除入口有效，删除后列表中不存在任务，其他任务仍可使用。
- Herdr 替身设为不可用，另分别模拟目标 pane 已消失、pane 仍存在但无 Agent；删除均能完成，且不会为删除发起远端启动、派发或关闭命令。
- 暂停后台启动或派发在可控边界，执行删除后再释放后台响应；验证任务、绑定和会话不会恢复，不启动新的后续步骤，不重发提示词，不影响新建同名任务。
- 用真实 SQLite 文件关闭重开验证删除持久化和中断恢复；验证未决记录不会重新阻塞其他任务或重新占用 pane。
- 验证取消确认不改变数据；重复点击或并发删除结果一致；数据库失败保留卡片并可重试。
- 原生桌面验收使用隔离数据构造同类未知启动任务，从卡片实际点击删除，确认卡片消失并在重新打开应用后仍不存在；Herdr 断开和目标窗口缺失分别验收。不得以模拟 IPC 测试代替原生桌面验收。
- 测试断言围绕用户可观察行为、持久化结果及外部调用，不绑定内部函数布局。实施后运行受影响的前后端测试和构建检查，并单列尚未完成的真实环境验收。

## Out of Scope

- 修复最初的 `agent_not_found` 启动时序问题。
- 修复或重新设计“核实启动结果”、自动恢复和拖动状态流转。
- 新增“放弃并删除”按钮、强制删除模式或额外确认步骤。
- 自动关闭 Herdr 窗口、终止底层 Agent、撤回已经发送的提示词或回滚外部文件修改。
- 改造项目删除、归档或其他卡片编辑操作。
- 直接操作用户现有数据库删除“测试2”，或将本次规格发布视为产品代码已完成。
