## 真实 Windows 桌面证据

使用本次共享源码构建的独立 Tauri/WebView2 应用进程、独立 SQLite 数据目录和本次新建的专用 workspace；未重启用户应用或操作个人工作 pane。底层 CLI 为已安装的 Herdr preview，Codex CLI 显示 v0.164.0。

专用 workspace 为 `kanban-acceptance-refactor-1f72c090`。通过真实桌面表单创建 A/B 两项任务，拖入开发中后核对：

1. 两任务只有一个 `kanban` Tab，pane 和 Codex 会话 UUID 各自不同。
2. 两张卡片可分别选中终端，输入未提交草稿通过真实 xterm/IPC/Herdr 路径显示；分隔线键盘调整使终端宽度从约 426.66px 变为 450.66px。
3. 完成 A 后其 pane 消失，B 的 pane 保留；完成 B 后最后的 kanban Tab 被 Herdr 移除。
4. 终止并重开本次验收应用，继续读取同一隔离 SQLite 后，A/B 均精确恢复到原会话。真实前台 argv 包含独立 `--no-daemon resume <原 UUID> -C <任务目录>`。
5. 两任务恢复后均能完成并关闭所属 pane。只读检查对应 rollout，各自只有最初的一条 user.text 消息，未重发原提示词或发送恢复探针；终端草稿没有提交。

实际恢复过程包含一个异常分支：A 第一次恢复时，目标会话的写锁证据尚未就绪，现有保护返回 `flow.session_mismatch` 并保留 unknown 与预占；应用重开后调用现有核实入口成功取得精确会话并继续。只读诊断确认身份保护源码与实施前快照一致，随后观察到目标进程只持有目标会话写锁。该事件没有通过放宽校验或重复发送来绕过；本次没有修改等待时间或恢复规则。B 的恢复直接成功。

本次结果与图像保存于 `.scratch/kanban-first-refactor/acceptance/`：`state.json`、`started.png`、`completed.png`、`resumed.png`；脚本在同目录上级。早期脚本问题（按钮无障碍名称包含 N、终端切换后需等待连接和使用文本插入事件、测试进程退出方式）在验收脚本中修正，未改产品交互。最终结论依据完成后的状态和消息记录。

验收结束后，已按本次创建记录核验身份并关闭专用 workspace、验收应用及其 Vite 进程，保留隔离数据库和结果文件供复核。
