# Kanban 图片输入与缩略图验收

日期：2026-10-24。规格：[GitHub #30](https://github.com/legendxcheng/ContextSwitcher/issues/30)，子任务 #31、#32、#33、#34；原生阻塞关系为 `31 → (32、33) → 34`。用户随后确认采用缩略图、悬停删除及点击放大的交互。

## 实现

- 新建/编辑共用图片输入，PNG、JPEG、WebP 作为稳定附件保存，正文仅存图片 ID、名称和字节数。
- 图片显示为 120×120px 缩略图；默认隐藏删除按钮，悬停或键盘聚焦显示“×”，可删除及撤销。点击打开大图，Escape 关闭大图后返回任务表单并恢复焦点。
- 草稿与任务/操作引用分离；保存事务、失败保留草稿、迟到响应隔离、后台回收及孤儿准备释放已实现。解码与文件同步写入不持应用数据库锁，回收使用独立 SQLite 连接。
- 自动启动与手动派发把有序图片引用转换为稳定本地路径和明确读图要求；缺图不静默丢弃，未知结果不重发，恢复旧会话不重发历史图片。

## 界面验证

真实 Chrome + React/Tiptap，图片 IPC 使用预览替身；不是原生剪贴板或真实 SQLite 的证明。

- 默认两个删除按钮的透明度均为 0；鼠标悬停第一张时，其透明度为 1，另一张仍为 0。
- 点击缩略图打开大图，Escape 只关闭大图，任务表单及图片仍在，焦点回到原缩略图。
- 900×600、1280×800、1920×1080 下两张缩略图均为 120×120，保存按钮可达；最小窗口正文滚动、头尾固定。

## 真实 Windows 宿主、SQLite 与 Agent

使用独立 Tauri/WebView2 进程、独立数据库/附件目录和明确的测试 Herdr session，不替换用户正在使用的应用，不向个人工作 pane 发送任务。

- 经真实 Tauri IPC 导入 PNG、JPEG、WebP、预览读回、保存任务，再从真实 SQLite 列表读取相同正文；三种预览的原始字节均一致。
- 自动启动和手动派发各执行一条实际读图任务，均包含三种格式的图文正文。提示词只要求描述最后一张图的左上和右下，不提前透露颜色或形状。
- 两路终端都出现真实 `Viewed image`，并分别回答 `blue circle` 和 `orange triangle`；不是依据 CLI 成功或文件存在作出通过判断。自动任务观察到 done，手动任务完成回答后观察到 idle。
- 在最终共享工作区源码重新构建并重启隔离宿主后，两个任务的六张图片均重新读回；自动任务完成后恢复了原会话 UUID，恢复期间暂时不可读取的一张历史图片没有阻止恢复。恢复后再次完成通过。
- 另外对已完成的自动任务执行归档，并通过已打开的合法草稿读取同一原图，确认归档没有删除图片。
- 手动任务关闭测试 workspace 的最后一个 pane 后，Herdr 已移除该 workspace，完成核实返回 `workspace_not_found` 警告。本次没有把该关闭核实记为成功，也未扩展修改已有 Herdr 生命周期规则；原操作事实及图片引用保留。
- 首轮测试项目缺少权威默认目录，自动启动产生 `flow.directory_missing`；未自动重发。为隔离测试项目显式选择已存在的测试目录后，使用新的测试任务完成验收。原失败证据保留。
- 临时测试脚本和完整隔离结果位于本地 `.scratch/kanban-image-input/native/`，不提交运行数据库、会话日志或个人窗口内容。
- 原生宿主及真实 Agent 证据来自共享工作区构建；上述独立提交快照仅执行自动化和构建检查，未单独重复原生宿主/Agent 验收。
