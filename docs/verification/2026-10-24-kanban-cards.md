# Kanban 紧凑卡片、优先级和归档验收

日期：2026-10-24。规格：[GitHub #12](https://github.com/legendxcheng/ContextSwitcher/issues/12)。用户补充：移除列底部新增区域，只保留顶部新建任务按钮。

## 实现范围

- 紧凑矩形卡片，标题最多两行；隐藏时间、重复状态和常驻派发信息；编辑、删除及完成卡片归档均使用图标。保留异常核实与清理恢复入口。
- 顶部按钮或 N 打开名称/优先级表单，创建成功后打开编辑侧栏；列底部无新增区域。创建失败保留输入，取消不创建，下一次默认为一般。
- normal / high / urgent 持久化，创建与编辑均可选择。后端各列按紧急、优先、一般，再按创建时间、ID 稳定排序。
- 迁移版本 4、5 分别增加 priority 与 archived_at。旧任务为一般且未归档；不会重建或清空历史数据库。
- 归档仅适用于 done，事务检查未决派发、生命周期操作和未完成清理，原子写入归档时间并释放独占绑定。保留任务、会话、派发和操作历史；不关闭 Herdr pane、不停止 Agent、不发送提示词。
- 独立派生 cleanup_required：失败启动不会掩盖先前完成清理失败。归档后的编辑、状态变更、开始/派发、修复绑定及终端目标解析被拒绝。
- 归档成功先更新本地列表/统计再重查，列表刷新失败不会使已归档卡片重新出现。

## 真实 Windows Tauri / WebView2 / SQLite

使用本次构建的调试可执行文件、隔离 KANBAN_DATA_DIR 和专用 WebView2 profile，通过其 CDP 调试入口操作真实 React 界面与 Tauri IPC；没有替换任务 API。

- 实际顶部创建时选择紧急，编辑回显正确；通过笔按钮键盘 Enter 打开编辑，修改优先级后顺序更新。
- 实际归档图标支持键盘 Space，卡片及统计移除；重复归档成功，无额外确认弹框。
- 归档后直接调用编辑、移动、开始和绑定修复 IPC 均返回 task.archived。
- 关闭并重新启动隔离桌面进程后，优先级、排序及归档仍保持。N 打开新建表单，默认一般，Escape 取消。
- WebView2 实测普通卡片 80 CSS px，两行长标题 98 CSS px。900×600 布局通过 WebView2 CDP 视口模拟核查；实际渲染无卡片横向溢出，看板不足宽度时横向滚动。该项不是物理显示器 DPI 或系统窗口拖放验收。
- 开发中状态的窄列外观使用隔离数据库中人工构造的无绑定任务，只验证排版及异常入口，不声称该任务实际启动了 Agent。
- 最终构建使用隔离库构造“完成清理失败 → 启动失败”历史，界面仍禁用归档并显示重试；归档 IPC 返回 archive.cleanup_required；实际点击清理重试成功后可归档。
- 真实 WebView2 发现按钮起手仍可触发卡片拖拽，补充 wrapper 指针起手检测后复测通过：SVG 图标内部起手也取消 dragstart，不写入拖拽任务；卡片正文拖拽保留。新增用例先失败后通过，Spec 审查复核无剩余问题。
