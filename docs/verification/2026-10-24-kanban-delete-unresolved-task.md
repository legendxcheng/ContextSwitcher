# 异常任务删除验收记录

日期：2026-10-24。规格：[GitHub #20](https://github.com/legendxcheng/ContextSwitcher/issues/20)。

## 实现范围

原删除按钮允许未决启动/派发、失败和待清理任务。沿用确认框，删除本地事务不依赖 Herdr；释放绑定、会话及查看连接，保留历史操作事实。任务缺失后，后台工作和重启恢复不再恢复卡片或写回占用，不新增数据表。

## 回归证据

- 共享工作区全套前端 83 项、Rust 73 项测试通过；5 项既有 Herdr live 测试未运行。类型检查、生产构建、Rust 格式检查和独立 debug 桌面构建通过。前端保留既有大 chunk 提示。
- 前端先复现 unknown 卡片删除按钮 disabled；修改后通过。参数覆盖 pending、unknown、failed、派发 pending/unknown、待清理，并覆盖取消、失败可重试和重复点击。
- 后端先复现删除发生在 available 返回时仍创建 pane，以及后台异常回写修改删除前操作记录；修改后通过。应用服务测试使用真实 SQLite、外部 Herdr 替身，在查询、创建、准备、会话查询、派发返回边界删除任务。
- 事务失败通过 SQLite trigger 注入，确认任务和绑定一起回滚；删除成功后同名新任务可以认领释放的 pane，迟到的旧操作不能影响新任务。
- 文件数据库关闭重开后任务仍不存在；后台启动及重复旧操作不能重新提交。历史未知派发未被改写为成功或未发送。

- 双轴审查发现的查询返回后创建/关闭竞态，已增加真实 CLI adapter + 本地子进程响应夹具回归：分别暂停 workspace 查询和关闭前身份查询，删除任务再放行，确认不产生后续创建或关闭命令。测试先失败后通过。
- 手动派发弹窗允许等待中通过原取消按钮或遮罩收起；真实派发入口的组件测试覆盖收起后删除、迟到结果不恢复卡片。后台回复不会关闭另一个新弹窗或强制选择旧任务。

- 删除成功后立即本地移除卡片，再刷新列表；已验证随后列表读取失败不会继续显示已删除卡片。

## 原生桌面证据

独立 Windows Tauri/WebView2 进程、真实删除 IPC、隔离 SQLite。测试只读取个人数据库的结构与迁移版本来建立空测试库，没有复制任务正文，也未修改个人任务。

脚本：`.scratch/delete-task/native_verify.py`；结果：`.scratch/delete-task/native-results.json`。

- 在线 Herdr、目标 pane 已缺失：实际点击原删除按钮，依次删除启动 unknown、派发 unknown、清理失败三张卡片；刷新及进程重启后仍不存在；绑定释放，原未知派发证据保留。
- CLI 不可用：使用无效的隔离 session 参数使 CLI 查询失败，同样实际删除三张异常卡片，刷新和进程重启检查通过。这证明 CLI 失败不阻塞删除，不等同于测试物理网络断开。
- 前后截图保存在上述脚本输出目录；未向个人 Herdr pane 发送提示词或关闭任何个人 pane。

## 边界

删除不撤回已经交给 Herdr 的请求，也不终止底层 Agent；已开始的请求可能完成，后续工作及其结果不能恢复已删除任务。未新增或验收远程取消协议。

本次不修复首次 `agent_not_found` 启动时序和“核实启动结果”入口；也未通过数据库直接删除用户的“测试2”。
