## 实现与证据边界

拖入开发中立即显示目标列和准备提示；本地事务保存启动快照，后台线程执行文件引用读取与 Herdr 生命周期。业务状态、派发结果和绑定有效性仍在实际成功后提交。通知和前台 2 秒查询对账，切项目不取消启动，完成不抢回用户选择。明确失败提供重试，未知结果保留证据并先核实。

TDD 首个组件用例在旧代码上失败：启动请求未返回时开发中列找不到卡片。实现后通过。服务用例通过持有准备闸门，验证受理先返回、操作可查询、重复请求不再执行，且另一个任务仍可编辑。

## 原生宿主验证

使用独立 Windows Tauri/WebView2、真实 SQLite 和外部 Herdr CLI **测试替身**。替身在 Agent 启动命令中延迟 30 秒；没有派发到真实 Herdr/Codex。应用和数据库位于 `.scratch/async-start-native/`，不重启用户正在使用的应用。

- 原生拖放后首个绘制帧已将卡片移入开发中，测得反馈约 **14.2 ms**。这是一轮本机采样，不是性能分位数或长期保证。
- Agent 尚未完成准备时，用相同操作 ID 再次受理约 **7.6 ms** 返回 pending；没有重复发送。
- 30 秒等待期间，通过界面新建任务成功，切到其他项目再切回仍显示准备状态。
- 准备期间 SQLite 的业务状态仍为 todo，Flow 的目标列为 in_progress。
- 准备完成后通知刷新，业务状态变为 in_progress、生命周期 succeeded，当前任务终端连接成功，提示词只发送一次。
- 已目视检查准备中截图。脚本、截图与结果：`.scratch/async-start-native/verify.cjs`、`preparing.png`、`ready.png`、`results.json`。
